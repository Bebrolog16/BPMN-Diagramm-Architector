# BPMN Architect

Локальный генератор и редактор BPMN-диаграмм. Изменения проходят через просмотр плана, ручное подтверждение, создание версии и сохранение полной истории сессии.

## Локальный запуск

Нужны Python 3.10+, Ollama и модель `qwen2.5-coder:7b-instruct`.

```bash
ollama pull qwen2.5-coder:7b-instruct
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn web.app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000` и создайте аккаунт по логину и паролю. В профиле можно изменить никнейм и фото, а для смены пароля требуется указать текущий. Пароли хранятся как PBKDF2-хеши, вход поддерживается случайным HttpOnly cookie. Сессии чатов из прежней версии при первом запуске можно сохранить: они будут привязаны к первому созданному аккаунту. Дальше история каждого аккаунта изолирована.

База `data/bpmn_architect.sqlite3` хранит аккаунты, сессии входа, сообщения, планы и все версии диаграммы. Папка `data/` исключена из Git. Можно создавать несколько чатов, продолжать правки после перезапуска, переключать текущую версию и скачивать BPMN.

Ollama должен быть доступен на `http://localhost:11434`. Настройки: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT_SECONDS`, `MAX_GENERATION_ATTEMPTS`, `BPMN_DATA_DIR`.

## Docker

```bash
docker compose up --build
```

Интерфейс опубликован только на `127.0.0.1:8000`; история лежит в именованном Docker volume `bpmn-data`. Compose задаёт пользователя без root, read-only файловую систему, writable volume только для данных, `no-new-privileges`, удаление Linux capabilities, лимиты процессов/памяти/CPU и временный раздел `/tmp`.

В Compose по умолчанию Ollama доступен через `host.docker.internal:11434`. Если Ollama слушает только loopback и соединение из контейнера не проходит, настройте его сетевой bind и firewall так, чтобы порт 11434 был доступен Docker-хосту и закрыт для ненужных устройств. Для Docker Desktop имя `host.docker.internal` направляет контейнер к сервису на хосте.

Docker здесь ограничивает приложение как процесс. Ответ модели по-прежнему интерпретируется безопасным ограниченным Python-подмножеством; произвольные импорты, циклы и файловые операции не исполняются. Не монтируйте Docker socket или домашнюю папку в контейнер.

## Изменения диаграммы

1. Опишите новую диаграмму или изменение существующей — планы и ответы формируются на русском языке.
2. Просмотрите план и нажмите **Применить план**, чтобы применить его, или **Отклонить**.
3. Новая версия сохраняется отдельно; старые варианты остаются в списке версий и могут быть выбраны как текущие.

При следующей правке модель получает программу текущей диаграммы и недавний контекст, а также просьбу сохранить все части процесса, которых не касаются изменения. Полная история остаётся в SQLite и показывается в панели чата.

Поддерживаются задачи, события, пулы, дорожки, XOR/AND/OR шлюзы, условия ветвлений, sequence/message flows и BPMN DI координаты. Подробности SDK находятся в `core/prompts.py`.

## Границы и данные

- Интерфейс по умолчанию доступен только на loopback. Если публикуете его в локальную сеть или интернет, используйте HTTPS и настройте ограничение частоты попыток входа на reverse proxy.
- История хранится локально в SQLite без шифрования. Не сохраняйте там секреты и сделайте резервную копию `data/`, если история важна.
- Docker Compose не запускается в этой среде, где Docker CLI отсутствует; файл конфигурации подготовлен, но запуск контейнера нужно проверить на машине с Docker.
- BPMN экспорт проверяется на корректность XML и внутренние DI ссылки; официальная XSD-проверка BPMN 2.0.2 пока не подключена.
